How Metadata Columns Are Built

  1. Files are scanned from configured folders and extension filters.
  2. Only top comment block lines are read for metadata extraction.
  3. Metadata lines follow: config-service: key=value.
  4. Any discovered key becomes a dynamic table column.
  5. Missing values remain blank; last_edited always comes from filesystem timestamps.

Selection Checkbox Direction

The catalog selection checkbox capability remains available as part of the normal catalog workflow rather than being hidden behind a separate toggle.

  • This keeps selected and unselected rows available for direct filtering.
  • This uses a fixed first-column checkbox so row-click viewing behavior remains unchanged.
  • This also supports future ordered file-selection workflows without changing row-click viewing behavior.
  • Standalone catalog behavior and provider deployments without the catalog feature should continue to operate independently.

File Change Refresh

The catalog detects source file changes from file paths, sizes, and modification timestamps. The browser refreshes rows on the configured interval, defaulting to 120 seconds.

  • Updated files are re-indexed so metadata columns reflect the latest file headers.
  • Automatic refresh pauses while any selection checkbox is active, preserving ordered selections.
  • Reloading the page always fetches the latest catalog rows immediately.

Callback Apply Mode

Apply button appears when a callback URL is provided in the catalog page query string.

  • The callback receives the tickbox-selected files in the order they were selected.
  • The checkbox column stays available even when no callback is supplied, so standalone filtering behavior remains unchanged.
  • When the callback succeeds, the catalog attempts to return the normalized file list to the opening server console window and then closes the popup.

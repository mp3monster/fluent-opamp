Metadata as Environment Variables

How metadata keys are separated from normal environment variables, edited in the UI, and written back to files.

Back to Config Editor

How It Works

Metadata variables are entries in the top-level Fluent Bit env section that start with _metadata.. In the UI, these are shown in a dedicated panel and the prefix is hidden so you can edit concise key names.

When saving or rendering to file, the prefix is always restored, so a key shown as config_version is written as _metadata.config_version.

Preset Metadata Options

The panel uses a selectable/creatable metadata key field so you can choose defaults or type custom keys.

  1. Fluent Bit Version: key fluent_bit_version, value selected from configured versions.
  2. Configuration Date: key configuration_date, automatically set to the current date when edited.
  3. Configuration Version: key config_version (aligned with pre-commit/webhook naming).

You can also add any custom metadata key/value pair.

Header Comments

Header comments let you maintain free-text notes at the top of a saved file. The editor shows plain text without comment markers, and the correct comment prefix is restored on save: # for Fluent Bit / Fluentd text and // for JSON documents.

Existing top-of-file comments are loaded into this field when a configuration is opened.
